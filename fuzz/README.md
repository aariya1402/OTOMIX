# Fuzz Corpus (P07-T02-S02-M01)

Deterministic container-parser fuzz corpus. Generated by `generate-corpus.ts`
with seed `0x07000001`; re-running produces byte-identical output.

## Layout

- `fuzz/generate-corpus.ts` — generator (PRNG + 3 base containers + 4 mutations)
- `fuzz/decoder.fuzz.spec.ts` — Vitest harness (runs inline; 300 files, 5 s each)
- `fuzz/corpus/` — generated binaries (gitignored)
- `fuzz/manifest.json` — generated class+format map (gitignored)

## Design: inline, not worker_threads

Earlier iterations used `worker_threads` with `resourceLimits: { maxOldGenerationSizeMb: 512 }`.
That failed because `packages/core/dist` is ESM with extensionless relative imports
(e.g. `from './config/analysis'`) — Node's native ESM resolver rejects those, but
Vite's resolver (used by vitest) handles them fine. Fixing core's dist is tracked as
supplement **GAP-021**.

The current harness runs `decodeAll` inline via vitest:
- **timeout** — `setTimeout` per file, flag checked after `await`
- **heap cap** — `process.memoryUsage().heapUsed` before, after each file, and after a
  forced GC; assertion is `peakDelta <= 512 MB`
- **"worker escape" (AC4)** — expressed as "no exception propagates out of `decodeAll`".
  `decodeAll` is designed to catch internal failures and return
  `{ ok: false, error, message }`; a non-zero counter here means an uncaught throw.

## Classes (75 files each, 300 total)

| Class | Mutation |
|-------|----------|
| `truncated` | Base container cut at random offset (< full length) |
| `oversized` | Header size field set above actual byte count |
| `recursive` | Appended nested LIST/INFO, extra ID3v2 headers, Vorbis count mismatch |
| `garbage` | Valid magic prefix + random tail |

Format distribution: `wav`, `mp3`, `flac` cycling by file index.

## Run

    pnpm vitest run --project fuzz

Or on-demand via GitHub Actions: "Fuzz Corpus (Nightly)" workflow.

## Acceptance (AC4)

All 300 files terminate <= 5 s, JS heap delta <= 512 MB, 0 unhandled exceptions,
0 bad-shaped results.
